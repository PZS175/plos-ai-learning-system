# PLOS AI · 作品介绍

> 一个能装进普通家用电脑、断网也能用的 AI 个人学习操作系统
> 版本 2.3.1 ｜ Windows 桌面端 ｜ 全部 AI 推理在本机完成

---

## 一、先说清楚这是一个什么东西

PLOS AI 是我自己做的一套**桌面学习软件**。它不是"又一个聊天机器人"，也不是"又一个搜题 App"，而是把中学生每天真实会用到的学习动作——导入讲义、问问题、拍错题、整理错题本、复习、练习、组卷、排学习计划、看学习数据——全部串成一条闭环，并且**所有 AI 能力都跑在本地**，拔掉网线照样能用。

打开它是一个普通的 Windows 桌面程序（PyQt6 写的原生窗口，不是浏览器套壳），安装包约 405 MB，里面自带数据库、向量库、插件系统和一个"离线演示数据"开关。它会自动识别你这台电脑的配置，在 3B 和 7B 两档本地大模型之间挑一套合适的：内存 16 GB 以上跑 7B，8～12 GB 跑"7B 文本 + 3B 视觉"，只有 7 GB 以下才退到全 3B 并把重资源功能关掉。

我给它起名叫 PLOS，是 Personal Learning Operating System 的缩写。之所以敢用"操作系统"这个说法，是因为它确实在做一个"平台"该做的事：有账户体系、有插件市场、有数据备份与还原、有主题与偏好设置、有统一的任务栏与消息中心。

### 当前规模（可核对的数字）

- 代码：`src/plos/` 下约 **4.4 万行** Python
- 界面：**24 个面板模块**（对外归成 19 项主功能）+ 主窗口、主题、Toast、线程池等公共组件
- 业务：**41 个服务模块**，其中 **29 个**由 `AppContext` 服务容器统一装配
- 数据：**30 张 SQLite 表**，**5 个版本化迁移**（`PRAGMA user_version` 逐级升级）
- 插件：**14 个内置** + **4 个商店插件**
- 测试：**304 项** pytest 用例 + **41 项**"学生一天"端到端检查
- 交付：PyInstaller 目录模式产物 + Inno Setup 安装包（405 MB）

### 运行环境

- 系统：Windows 10 / 11（64 位）
- 推理后端：本机 Ollama（文本 qwen2.5、视觉 qwen2.5-vl、向量 nomic-embed-text）
- 内存：8 GB 可跑（自动降为 3B），16 GB 以上体验最佳；无独立显卡也能跑（纯 CPU 推理）
- 网络：**不是必需项**。联网只用于两处可选能力——按需下载模型、教材导入（内置浏览器打开国家中小学智慧教育平台）。设置里有"强制纯离线锁"，打开后所有在线入口直接隐藏。

## 二、为什么我要做这个

起因很简单：我自己（和身边同学）在用学习类工具时，遇到的痛点几乎是一致的。

第一类是**贵**。学习机动辄三四千元，很多功能还要按年付费，普通家庭不容易负担。

第二类是**隐私**。拍照搜题类 App 要把题目照片传到云端，一个学生的错题本其实就是他学习薄弱点的完整画像，我不太愿意把这些照片交给不认识的服务器。

第三类是**不闭环**。通用 AI 聊天工具很聪明，但它"聊完即忘"——你昨天问过的题，今天它不记得；你错过的知识点，它不会主动帮你排复习计划。而记忆类软件（比如 Anki）擅长复习，却不理解题目。

第四类是**不讲教学法**。搜题 App 直接把答案给你，抄完就过去了。可真正有效的学习是"被追问"的过程。

所以我想做的东西目标很明确：**让一个普通学生，用一台普通电脑，获得一个不联网、免费、并且懂一点教学法的 AI 学习助理**。

## 三、整体框架结构

### 3.1 分层：四层，层间只走接口

```
┌────────────────────────────────────────────────────────────
│  界面层  src/plos/ui/
│  主窗口（侧边导航 + 顶部标签栏 + 任务栏 + 托盘）
│  24 个面板 · 主题令牌与 QSS · Toast · 公式混排控件 · 线程池
│  铁律：面板只做「展示 + 交互」，不写业务逻辑、不直连数据库
├────────────────────────────────────────────────────────────
│  服务层  src/plos/services/
│  对话 · 知识库(RAG) · OCR · 图片增强 · 错题本 · 错题试卷导出
│  闪卡(SM-2) · 自适应练习 · 组卷 · 学习计划 · 统计 · 诊断报告
│  术语 · 思维导图 · 示意图 · 语音(ASR/TTS) · 学习包 · 备份 · 用户
│  铁律：不 import Qt —— 所以能无界面测试、能被 CLI 复用
├────────────────────────────────────────────────────────────
│  AI 层  src/plos/ai/            数据层  src/plos/db/
│  ModelManager 门面（多后端）      Database 单例 + schema + 迁移
│  Ollama / llama.cpp / 云端        SM-2 记忆曲线 · 向量库封装
├────────────────────────────────────────────────────────────
│  核心与工具  core/ · utils/ · config/ · plugins/
│  枚举 · 领域模型 · AppContext 容器 · 配置与硬件探测 · 日志 ·
│  崩溃捕获 · 路径 · 数学渲染 · LaTeX 清洗 · 插件管理
└────────────────────────────────────────────────────────────
```

这样的分层不是为了好看，而是有具体好处：服务层不依赖 Qt，我才能在命令行里跑完整的"学生一天"端到端脚本；界面层不直连数据库，换界面（比如以后做移动端）不会动到业务。

### 3.3 服务装配：一个容器管住 29 个服务

所有服务集中在一个 `AppContext` 数据类里构建，按依赖顺序装配：

```
AppContext.build(model_manager)
  UserService → StatisticsService → SearchService → SessionManager
  → ErrorBookService → FlashcardService(挂统计) → PracticeService
  → ExamService → RAGService → TeachingStyleService(必须先于对话)
  → ChatService → OCRService → InputRouter → StudyPlanService
  → NoteAnnotationService → KnowledgeGraphService → DiagnosticReportService
  → TerminologyService → MindMapService → DiagramService → ASRService
  → WebClipService → BackupService → LearningPackageService → …
```

顺序不是随便排的：教学风格服务必须先于对话服务（要把风格注入 system prompt）；错题本建好后要**回挂**学习计划服务，否则"新错题自动插入复习任务"这条链路断掉。收益很直接——主窗口的构造函数从几十行服务装配变成几行，测试和预览工具还能只替换其中一部分。

### 3.4 三条核心数据流

**① 问答（RAG 检索增强）**

```
用户提问
  → 是否需要检索？(可选开关)
      → 本地嵌入模型把问题向量化（nomic-embed-text）
      → ChromaDB 检索最相关的 top_k 片段
      → 计算真实余弦相似度作为"相关度"展示
  → 拼装消息：system(教学风格 + 模式约束) + 历史 + 检索片段 + 本次提问
  → 本地大模型生成（支持流式，逐字回界面）
  → 落库会话历史 / 更新统计
```

**② 拍照识题（图片 → 结构化题目）**

```
图片（拍照/截图/拖拽）
  → OpenCV 图片增强（去笔迹、背景净化、对比度、锐化、倾斜校正、四点透视）
  → 本地视觉模型识别文字
  → 文本格式化服务（清乱码 → 补全 \( \) 公式标记 → 归一数学符号）
  → 文本模型把整页切分成若干道独立题目
  → 结构化 {题目, 答案, 解析} → 写入错题本（保留公式标记）
  → AI 打标（知识点/题型/难度，中文）
  → 触发学习计划动态调优 → 仪表盘与薄弱知识点刷新
```

**③ 错题驱动的计划调优（这个闭环是"活"的关键）**

```
ErrorBookService.add_error()
  ├─▶ SQLite: error_book / user_stat
  ├─▶ StudyPlanService.adjust_plan_on_error_added()
  │      → 取当前活跃计划 → 插入"复习：某某知识点"任务 → 记录调优说明
  └─▶ 掌握度变化 set_mastery()
         → adjust_plan_on_mastery_changed() → 任务优先级重排
```

也就是说，学生每记一道错题，计划都会跟着变；每标记一次"已掌握"，计划会把对应任务降权。数据不是躺在表里，而是反过来驱动安排。

### 3.5 并发与线程模型

界面卡不卡，取决于这件事做没做对。所有耗时动作（模型推理、文档解析、向量化、试卷导出、备份打包、公式渲染）都走 `QThreadPool` 里的 Worker，通过信号回主线程：

- 主线程只做绘制与交互，任何一处都不允许同步等模型
- 渲染结果带**自增 token**，回来时先比对——否则连续切换两道题，先算完的会覆盖后算完的
- 主题相关的取值（`is_dark_theme()`）必须在主线程算好再传进后台，后台线程碰 `QApplication` 会直接崩
- 数据库用进程内 `RLock` + `transaction()` 原子上下文，SQLite 开 WAL、外键、`busy_timeout`
- 淡入动画的 `QGraphicsOpacityEffect` 不能在自己的 `finished` 回调里销毁，必须延迟到下一轮事件循环释放

### 3.6 数据与文件布局

30 张表按用途分组（全部本地 SQLite，文件可整体拷贝走）：

- **账户与配置**：`users`、`settings`、`user_stat`、`teaching_style_config`
- **知识库**：`documents`、`chunks`（向量本体在 ChromaDB 目录）
- **题目与错题**：`error_book`、`ocr_records`、`subjective_grades`、`exam_papers`、`exam_paper_questions`、`practice_questions`、`practice_records`
- **复习与计划**：`flashcards`、`review_schedules`、`study_plans`、`study_plan_tasks`、`study_plan_adjustments`
- **笔记与词条**：`notes`、`note_annotations`、`terms`、`mindmaps`
- **统计与日志**：`statistics_records`、`study_logs`
- **对话**：`conversations`、`messages`
- **其他能力**：`asr_records`、`diagram_records`、`learning_packages`、`textbook_cache`

磁盘布局：`data/`（数据库、向量库、图片、附件、自动备份）、`config/config.toml`、`logs/plos.log`。多用户在同一套表里靠 `user_id` 隔离，删除用户会级联清理他名下的全部数据。

这些目录默认就在程序自己的文件夹里（便携设计：整个文件夹拷走就带走了全部数据）；如果该位置不可写（例如装到了权限受限的目录），程序启动时会自动改用当前用户的本地应用数据目录，而不是直接启动失败。

### 3.7 扩展机制：插件系统

主程序不打算把所有小工具都塞进来，所以做了插件机制：每个插件是一个目录，含清单 `plugin.json`（名称、版本、作者、描述、入口文件）和入口 `main.py`，入口只需暴露一个 `register(ctx)`，用 `ctx.register_panel(...)` 把自己的面板注册进主窗口。加载用 `importlib` 动态执行，模块名形如 `plos_plugin_<插件id>_main`，插件加载失败只影响它自己，不会带崩主程序。

目前内置 14 个（番茄钟、函数图像、元素周期表、成绩簿、口算、公式手册、方程配平、课程表、古诗词、抽签点名、单位换算、学习日志、考试倒计时、计算器），商店 4 个（成语词典、打字测试、历史时间轴、不规则动词）。

### 3.8 技术选型与理由

| 选型 | 为什么选它 | 放弃了什么 |
|---|---|---|
| PyQt6 原生控件 + 手写 QSS | 离线、启动快、内存可控、能精确做出扁平桌面软件质感 | 全站式 Web UI（体积大、内存高、启动慢，还容易做成"网页感"） |
| SQLite（WAL + 外键 + 迁移） | 单机零部署，事务安全，备份就是拷文件 | MySQL/Postgres（要装服务，学生装不上） |
| ChromaDB + nomic-embed-text | 本地向量检索，持久化到目录 | 云端 embedding（隐私、费用、断网不可用） |
| Ollama 统一后端 | 一条命令拉模型、量化后 CPU 可跑、自带 keep_alive 常驻 | 纯 llama.cpp（要自己管 GGUF 与参数）、云端 API（数据外流） |
| 自研 LaTeX→HTML 渲染 | 零依赖、任何文本控件都能用、可复制可导出 | matplotlib（打包体积 + 每次渲染都有延迟）、MathJax（必须浏览器内核） |
| PyInstaller 目录模式 + Inno Setup | 启动快、安装包可自定义、能加自检 | 单文件模式（每次启动解压，慢） |

## 四、核心创新点

我把"创新"理解为**别人没这么做、或者这么做明显更好的地方**，下面每一条都写清楚：解决什么问题、怎么做的、难在哪。

### 创新点 1：离线优先的"错题驱动"学习闭环

**问题**：市面上的工具要么只会做一件事（搜题、背单词、组卷），要么各自为政——错题归错题、复习归复习，学生得自己拿主意"下一步学什么"。

**做法**：把错题本做成整个系统的"数据源"，让它同时驱动四件事——闪卡生成、自适应出题、学习计划调整、薄弱点排行。**最有价值的设计是计划会被错题改变**：新增一道错题，系统会给当前活跃计划自动插入一条"复习：某某知识点"的任务，并留下一条可查的调优记录；把错题标记成"已掌握"，对应任务会被降优先级。计划从一张静态表格变成一份会随学习状态变化的安排。

**难在哪**：错题本服务与计划服务是**双向依赖**（计划要读错题的掌握度，错题要触发计划调整），普通的构造注入会死循环。我的解法是后置绑定（`set_study_plan_service`），在 `AppContext` 里按顺序装配完再回挂。

### 创新点 2：零依赖的 LaTeX 公式混排渲染引擎

**问题**：这是一个理科学习工具，"公式显示不出来"等于废掉一半功能。而 Python 桌面端做公式排版通常只有两条路——matplotlib 渲染成图片，或者嵌入浏览器内核跑 MathJax。

**做法**：我自己写了一个 LaTeX → HTML 的转换器，直接跑在 Qt 富文本上，**不依赖任何第三方渲染库**：

- 行内公式的分式用 `⁄` 线性写法（Qt 行内元素无法堆叠），乘法与根号用 `√` + 上划线实现
- **独立公式用一张两行的表格做真上下结构**：分子一行、分母一行、中间用 `border-bottom` 当分数线，运算符用 `rowspan='2'` 跨两行
- 上下标用 `<sup>/<sub>`，方程组、不等式、化学式都做了映射
- 每个公式外面套一个自定义协议锚点（`plosmath:` + base64 源码），于是鼠标悬停能提示、点击能复制源码、整段复制拿到的还是带标记的原文
- **兜底比渲染更重要**：解析失败就原样显示源码（不空白、不崩、不毁掉整段文字）；`$...$` 的判定极其保守（不跨行、长度有限、内容必须"像数学"、含中文一律当普通文本），所以"这件 $5 元，那件 $10 元"永远不会被当成公式

**难点与代价**：最初我用 matplotlib 实现，开发环境一切正常，但打包脚本里 matplotlib 在排除列表里（它太重），**装出来的 EXE 里公式全部退化成源码**——这是"开发机能跑不等于交付能用"的典型案例。换成自研渲染器后，安装包不再需要这个上百 MB 的依赖，渲染也从"每次生成图片"变成毫秒级的纯文本转换。

**再往前走一步是全链路覆盖**：公式不只要在聊天框里能看，还要能在树表格单元格（错题预览树、批量识别树）、批注列表、术语上下文、错题卡片标题里显示——为此我给 `QTreeWidget/QListWidget` 写了单元格委托，**只对真的含公式的单元格**改用富文本绘制，其余单元格完全走原生绘制路径（也就是说，不含公式的界面性能开销为零）。同时导出侧也要配套：Word 用 OMML 生成 Office 原生分数，PDF 用"分子/横线/分母"三段绘制出真正的上下结构。

### 创新点 3：不依赖模型的图片增强预处理

**问题**：手机拍的错题照片，背景是书桌、上面有自己的蓝笔圈画、纸还是斜的。直接把这种图丢给视觉模型，识别率会明显下降。

**做法**：在识别前加一道纯 CPU 的 OpenCV 预处理流水线，支持去笔迹（自动判别蓝/黑）、背景净化、对比度增强、文字锐化、倾斜校正、四点透视裁切、二值化。关键设计有两点：

- **区分"笔迹"与"印刷体"**：不是无脑按颜色阈值抠——印刷表格的框线、文字本身的笔画不能被误删。我做了笔迹掩码 + 矩形框豁免 + 线条抖动判别（印刷线是笔直的，手写线有抖动），只删掉真正的手写部分
- **只勾选"去笔迹"时不改动色调**：早期版本即使用户只想去掉笔迹，也会顺手做一次背景净化而改变整张图的色调，看起来像"程序把我的图改了"。现在检测用图与输出用图分离，只有显式勾选净化/二值化才改写色调

**效果**：整条流水线在 CPU 上 **0.1～0.2 秒**（一张 1000×420 的图），不占 GPU、不依赖任何模型，低配机器也能开。

### 创新点 4：带教学法约束的对话编排

**问题**：通用 AI 会直接把答案给你。但"抄答案"不是学习。

**做法**：把教学法做成**可切换的编排参数**，而不是一句写死的提示词：

- 教学模式：普通讲解 / 苏格拉底式（追问引导，不直接给结论）
- 输出约束：开启"不直接给答案"后，system prompt 会注入强约束，要求先给思路、留出让学生自己算的空间
- 讲解深度：基础 / 进阶 / 应试 / 研究四档，分别对应不同的展开程度与语言风格
- 教学风格服务：可配置鼓励式/严格式、讲解深浅、举例风格、语气，并注入 system prompt

这四处都落在同一套消息拼装逻辑里，所以风格、模式、深度可以自由组合，且对上层界面只是一组开关。

### 创新点 5：数据主权——从架构上保证"数据不出本机"

**问题**：讲"隐私保护"很容易，难的是**结构上就做不到外传**。

**做法**：

- 文本、视觉、向量三类模型全部走本地 Ollama；云端 API 是可选后端，默认不启用
- 设置里有**强制纯离线锁**：打开后界面上所有在线入口（云端配置、教材导入）直接隐藏，网络访问路径不可达
- 多用户数据在表级用 `user_id` 隔离，切换用户后互相看不到对方的错题，删除用户会级联清理他名下 20 多张表的数据
- 备份/还原有**回滚安全网**：还原过程如果中途失败，会自动恢复到还原前的状态，不会出现"还原到一半库坏了"
- 全局崩溃捕获 + 滚动日志，异常不会静默丢数据

### 创新点 6：按硬件自适应的模型套装与降级策略

**问题**：本地模型的尴尬是"好机器跑得动大模型、旧机器装不上"。

**做法**：探测内存/显存后落到三档套装（`7b` / `mid` / `3b`），并**按机器上真实存在的模型名做解析**（同系列不同规格的 base 名是一样的，必须同时比"base 名"和"参数量"，还要处理 `qwen2.5-vl` 与 `qwen2.5vl` 这类别名差异）；低配档位自动关闭视觉识别与图表组件，只保留文字能力，并如实告诉用户"功能已降级"，而不是假装能跑。

**这个点为什么值得单列**：测试时我发现"硬件推荐 7B 套装"实际跑的是 3B——只比 base 名会先撞上列表里靠前的 3B。这个 Bug 不报错、不崩溃，只是所有回答都变笨了，非常隐蔽。

### 创新点 7：把"能不能交付"当成功能来做

**问题**：Python 项目"我这能跑"和"别人装上能用"之间隔着很远。

**做法**：自建三层验证——

1. **304 项自动化测试**（离屏 Qt 运行），覆盖公式渲染、图片增强算法、试卷导出、备份还原、多用户隔离、闪卡闭环、每个面板的渲染
2. **41 项"学生一天"端到端脚本**：把数据目录指向沙箱（等价于全新安装），从建账号一路跑到备份还原，并**真的调用本机模型**，最后扫一遍运行期日志有没有 ERROR
3. **打包自检探针**：每次出 EXE 后，用隐藏开关启动打包好的程序，在里面真的做一遍"导入链完整性、插件资源、Word/PDF 试卷生成、OpenCV 图片增强、公式渲染"，全部通过才允许继续出安装包

## 五、一个学生一天会怎么用它

下面这条流程，就是端到端脚本里跑的流程（不是设想，是每次改动后真的会跑一遍的）。

**导入讲义。** 老师发的讲义拖进知识库，程序解析、切片、向量化。之后我问"二次函数在闭区间上的最值怎么求"，它先在自己的知识库里检索出相关段落（界面显示来源文件名与相关度），再结合讲义回答——所以它的讲法和老师一致，而不是另起一套。

**拍一道错题。** 照片先过图片增强：去掉我蓝笔画的圈、净化纸张背景、做倾斜校正与锐化（0.1 秒级，纯 CPU）。然后本地视觉模型识别文字，**自动补上公式标记**（模型读出 `f(x)=x^2-4x+3`，程序把它变成 `\(f(x)=x^2-4x+3\)`），再由文本模型把整页切成一道道独立题目。

**错题入库与打标。** AI 给出知识点、题型、难度；知识点必须是中文（早期没写这条约束时，小模型把"二次函数最值"翻译成了 `function / quadratic_function`，直接显示在错题本里，完全不可读）。错题同时点亮薄弱知识点排行。

**一键格式化。** "清乱码 → 补公式标记 → 归一数学符号"打包成一个按钮，全局可用（错题三个输入框、单张/批量识别结果、笔记、语音转写文本），而且是**幂等**的——连点两次结果一样，用户才不会怀疑程序乱改他的文本。

**导出练习卷。** 按知识点范围或手动勾选导出 Word / PDF，公式是**真正的数学排版**（Word 用 OMML 原生公式，PDF 分数是画出来的上下结构）。顺便说，这里曾有一个 18 MB 的 PDF 问题，见第七节。

**闪卡复习。** 错题一键变闪卡，SM-2 记忆曲线（1、3、7、15、30 天，答错回退），四档评分。

**自适应练习与组卷。** 按知识点出题，判分后给出"下一题建议难度"，难度跟着水平走；需要整卷时按"知识点 + 各题型数量 + 难度区间"组卷，导出"试卷 + 参考答案"两个文件。

**学习计划自动跟着你改。** 新错题自动插入针对性复习任务，掌握度变化重排优先级，每次调整都留下可查的记录。

**看数据。** 学习时长热力图、连续学习天数、每周报告、错题学科分布、闪卡正确率、掌握度汇总、薄弱知识点排行。

**数据安全。** 自动滚动备份（按天/按周，保留份数可配）+ 手动全量备份（含附件）+ 带回滚的还原 + 数据库完整性检查。

**换人使用。** 多用户严格隔离；演示模式可一键加载内置演示数据（16 道错题、12 张闪卡、3 个计划），断网也能把整条流程演完。

## 六、实现细节与工程取舍

### 1. 不阻塞界面是硬要求

公式渲染、文档解析、向量化、模型推理全部走线程池。这里有两个"看起来多余、其实必须"的细节：渲染结果带自增 token（防过期结果覆盖新结果）；主题色必须在主线程取值后传进后台线程（后台线程读 `QApplication.palette()` 会直接让进程崩）。加载指示器的显示策略也做过取舍：只有渲染真的超过 180 ms 才显示转圈——否则 1 ms 的渲染会先闪一下"渲染中"，反而显得卡。

### 2. 一个隐藏很深的进程崩溃

有一次我发现：打开文档阅读弹窗后**立刻按 Esc 关掉**，程序直接消失，没有异常栈，日志里什么都没有。定位很久才明白两件事叠在一起：渲染回调是 lambda 连到工作线程的，**不会随控件销毁自动断开**；而 PyQt 里**槽函数抛出未捕获异常会让进程直接 abort**。控件已释放、渲染结果姗姗来迟，回调一碰控件就抛异常，进程就没了。修法是给这两个回调整体兜底，控件没了就安静丢弃结果。

同一类问题还有一次更隐蔽的：淡入动画的 `QGraphicsOpacityEffect` 如果在 `finished` 回调里直接置空，会在动画自己收尾期间删掉它仍持有的对象，造成 use-after-free。

### 3. 测试环境里"莫名挂死"的两个原因

一是**模态框**：`show_success` 在没有注册 Toast 宿主时会降级成 `QMessageBox`，`exec()` 开模态事件循环，在离屏测试里就是静默卡死。二是 **`QApplication` 被 GC**：各测试模块自建的应用对象被回收后，`QThreadPool.globalInstance()` 跟着销毁，而 `ThreadPool` 里还缓存着旧对象，下一个模块丢任务就崩。修法分别是注册 Toast 宿主、用会话级 fixture 全程保活。

### 4. 中文显示的坑

`QSpinBox / QDoubleSpinBox` 的数字在字体回退路径下会渲染成数学符号，必须单独指定字体族；zh_HK 区域设置下 Qt6 数字输入框字形异常（区域数字符号映射）；PDF 导出必须显式嵌入中文字体，否则换台电脑打开就是方块。

### 5. 界面上的自我约束

所有样式用原生 QSS，颜色全部走主题令牌（**面板代码禁止出现十六进制色值**），深浅双主题 40 多个令牌一处改全局生效；全局扁平化，没有阴影悬浮、呼吸灯、渐变边框这类"网页特效"；新增能力一律下沉到细节入口，不做大页面大按钮——目标是"像桌面软件，不像弹窗广告"。

## 七、测试实录：一次"当学生用一遍"发现的四个真 Bug

功能写完不等于写完了。我写了一个端到端脚本，把整个数据目录指向沙箱（等价于"刚装好、第一次打开"），从建账号一路走到备份还原、换用户、双主题渲染，并且**真的调用本机模型**。跑完 41 项检查全过，但输出里藏着四个 Bug：

**① 四道题的练习卷，PDF 导出 18.68 MB。** 拆开 PDF 看对象，发现一个 17.47 MB 的流——那是被**完整嵌入的宋体字体文件**（宋体本身就有 17 MB）。学生在微信里根本发不出去。修法是保存前做字体子集化，只保留页面用到的字形：**18.68 MB → 52 KB**，缩小 360 倍，显示与可复制文本完全一致。

**② 知识库显示"相关度：-317.517"。** 向量库用 Chroma 默认的 L2 距离，嵌入向量不是单位向量、距离能到 300+，而代码写的是"相似度 = 1 - 距离"，于是唯一命中的那一段被标成最不相关，界面上是个负数。改成取回向量算真实余弦相似度（拿不到时单调压缩兜底），同一份讲义现在显示 **0.612**。

**③ "硬件推荐 7B 套装"实际跑着 3B 模型。** 只比 base 名会先撞上列表里靠前的 3B。它不报错、不崩溃，只是所有回答都变笨：3B 曾出过"开口向下的抛物线求最小值"这种自相矛盾的题（二次项系数为负，它只有最大值），换成 7B 就正常了。修法是同时比 base 名与参数量。

**④ 计划里七天任务长得一模一样。** 离线降级模板七天都是"数学 专项训练"，而任务列表只显示标题/科目/时长——一排完全相同的行，演示现场会以为程序坏了。改成带周几、每天换一个训练动作。

这四个问题的共同点是：**都不抛异常，测试全绿时也发现不了，只有真的当学生走一遍、并且认真看输出里每个数字，才会露出来**。

## 十、我知道它现在的不足

写得诚实一点，这些是我自己清楚的问题：

**模型规模就是天花板。** 3B 模型的数学推理经常出错，程序能做的是"有条件时用 7B、低配时如实告知降级"，没法凭空提升小模型的能力。物理上，一个 4 GB 的模型和云端大模型不在一个量级。

**视觉识别依赖内存。** VL 模型最小也要 3 GB 左右，识别一张图要十几到二十秒（首次调用含模型加载），低配机器上这个功能只能关掉。

**知识图谱是统计出来的，不是理解出来的。** 现在靠共现频次和错题统计画节点连线，能反映"哪两个知识点总是一起错"，但谈不上真正的知识结构理解。

**没有云端同步。** 多用户是同一台电脑上的多用户，换电脑要靠手动迁移备份文件。

**语音能力有限。** ASR 要额外装模型，TTS 用系统语音合成，自然度一般。

**主观题批改时好时坏。** 采分点抽取依赖模型，题目稍复杂就漏点，只能当参考。

**跨平台没做。** 目前只有 Windows 包。架构上（PyQt6 + SQLite + Ollama）应该能迁到 macOS/Linux，但我没有验证过，不想在作品里写没做过的事。

## 十一、接下来想做的事

1. **让错题本"活"起来**：现在错题相似度只用于展示，我想做同类题推荐和"重做时自动变式"，让学生做等价题而不是背原题。
2. **让计划调整可解释**：每条调优点开就能看到原因，比如"你周三错了两道二次函数题，所以我把周五的复习提前了"。

5. **混合检索**：关键词 + 语义，缓解"问法和讲义用词不一样就检索不到"。

## 十二、最后说几句

这个作品是从"我自己想要一个什么样的学习工具"出发做出来的，所以很多细节不是需求文档逼出来的，而是我自己用着别扭才去改的：公式必须能在错题本、闪卡、试卷、图表里都正常显示；备份必须能一键还原而不是只会导出；界面必须像桌面软件而不是网页弹窗；浅色深色都得能看（教室投影用浅色、晚上自习用深色）。

做它的过程中我最大的收获不是学会了 PyQt6 或者 RAG，而是学会了**不轻易相信自己**：程序不报错不代表它对，"测试全绿"也不代表它对。这次当学生用一遍，就在全绿的输出里揪出了四个真 Bug——一个 18 MB 的 PDF、一个负数相关度、一套没生效的高配模型、一份七天都一样的计划。写下这段介绍的时候，它们都已经修好并且有测试守着了。

如果这套东西能让一个买不起学习机的同学，在自己家里的旧电脑上获得一个说得过去的 AI 学习助手，我觉得它就值得做下去。
