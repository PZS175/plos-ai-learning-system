## 摘要

针对现有学习类工具价格高、需联网上传隐私数据、功能互不打通、缺少教学法约束这四个问题，本研究设计并实现了一套完全离线的个人学习系统 PLOS AI。系统在本地部署轻量化大语言模型（文本、视觉、向量三类），以错题本为核心数据源，把"导入讲义—知识库问答—拍照识题—错题入库—间隔重复复习—自适应练习—组卷导出—学习计划调优—学习数据分析"串成一条闭环，全部推理与数据存储都在本机完成，断网可完整使用。研究过程中解决的主要技术问题包括：在无第三方公式排版库的前提下实现全应用 LaTeX 公式混排；在 CPU 上实现不依赖模型的图片增强预处理（去手写笔迹、背景净化、几何校正）；让学习计划随错题与掌握度变化自动调整并保留可审计的调整记录。系统经过 304 项自动化测试、41 项"学生一天"端到端检查与打包产物自检，在配备 7B 模型的普通家用电脑上，图片增强耗时 0.1～0.2 秒、语义检索约 0.1 秒、对话回答 7～14 秒，安装包 405 MB，可在一台旧电脑上零成本部署。研究表明：在本地算力受限的条件下，通过"结构化工作流 + 提示词约束 + 程序化校验"的组合设计，可以让小参数模型在特定教育场景中达到可用水平。

**关键词：** 离线大语言模型；个人学习系统；错题管理；间隔重复；检索增强生成；数据隐私

## 1 研究背景

### 1.1 中学生学习工具的真实现状

我在自己和身边同学使用学习工具的过程中，记录了四类典型问题：

1. **价格门槛高。** 主流 AI 学习机动辄 3000～6000 元，部分功能还需按年付费，对普通家庭是明显负担。
2. **隐私风险。** 拍照搜题类应用需要把题目照片上传到云端服务器。一个学生的错题集合，实际上就是他知识薄弱点的完整画像，这些数据是否必要离开本机，值得质疑。
3. **功能不闭环。** 通用 AI 对话工具能解答问题，但不理解学习管理——昨天问过的题今天不再记得，错过的知识点也不会主动安排复习；而记忆类软件（如 Anki）擅长间隔重复，却完全不理解题目内容。
4. **缺少教学法约束。** 搜题类应用通常直接给出答案，学生会退化为"抄答案"；有效的学习应当包含思路引导与自我推演。

### 1.2 已有方案的能力对比

（详见本研究报告第 7 节创新点对比表）四类已有方案各自只解决了问题的一部分：学习机覆盖能力最全但价格高且封闭；搜题 App 便宜但依赖联网且直接给答案；通用 AI 对话能力强但没有学习数据沉淀；记忆软件算法科学但不理解内容。**"全离线 + 错题驱动的学习闭环 + 教学法约束"三者的组合，是当前方案共同缺失的部分。**

### 1.3 技术与政策背景

- 以 Qwen2.5 系列为代表的开源大模型提供了 3B / 7B 量级的可选规格，经 4 bit 量化后可在普通家用电脑的 CPU 上推理，实测响应时间进入可用区间；
- 本地推理工具（Ollama）把模型拉取与运行简化为一条命令，降低了部署难度；
- 检索增强生成（RAG）技术成熟，使得"结合学生自己的讲义回答问题"不再需要训练模型；
- 《中华人民共和国个人信息保护法》确立了个人信息处理的最小必要原则，为本地化处理提供了合规依据；
- 教育部关于加强中小学生手机管理等相关要求，说明学习场景对"可控、可离线"的工具存在真实需求。

## 2 研究目的与意义

**研究目的：** 设计并实现一套能在普通家用电脑上零成本部署、断网可用、数据不出本机，且把学习管理闭环真正打通的学习系统，验证"本地小模型 + 结构化工作流"能否在中学学习场景中达到可用水平。

**研究意义：**

1. **实用意义**：为预算有限的家庭提供一条不依赖付费硬件与订阅服务的学习工具路径；
2. **隐私意义**：以架构方式（而非承诺方式）保证学习数据不外流；
3. **方法意义**：验证"用提示词约束与程序化校验补偿小模型能力"这一思路在教育场景中的有效性；
4. **工程意义**：形成一套可复现的离线桌面端 AI 应用交付方案（打包、自检、安装、降级策略）。

## 3 研究内容

### 3.1 系统总体设计

系统采用四层结构，层间只通过接口交互：

- **界面层**：主窗口 + 24 个功能面板模块（对外归成 19 项主功能），只负责展示与交互，不写业务逻辑、不直接访问数据库；
- **服务层**：41 个业务服务模块（其中 29 个由统一的服务容器装配），承担对话、知识库、图像识别、错题、复习、练习、组卷、计划、统计、备份等全部业务逻辑；该层不依赖界面框架，因此可以脱离界面测试；
- **AI 层 / 数据层**：统一的模型管理门面负责文本、视觉、向量三类模型的多后端切换（本地 / 云端）；数据层负责数据库连接、版本化迁移、记忆曲线算法与向量库封装；
- **核心与工具层**：枚举、领域模型、配置与硬件探测、日志、崩溃捕获、公式渲染、文本清洗、插件管理。

### 3.2 关键功能设计

1. **知识库问答（RAG）**：讲义解析 → 切片 → 本地向量化 → 检索相关片段 → 与教学风格提示词一起拼装 → 本地模型流式生成；
2. **拍照识题链路**：图片增强 → 本地视觉模型识别 → 文本清洗与公式标记补全 → 切分独立题目 → 结构化入库；
3. **错题驱动的学习闭环**：错题入库自动触发学习计划调整，掌握度变化触发任务优先级重排，并保留可审计的调优说明；
4. **公式混排渲染**：自研 LaTeX → HTML 转换（不依赖第三方排版库），覆盖行内与独立公式，并贯通导出（Word 原生公式 / PDF 手绘上下结构）；
5. **教学法约束**：教学模式（讲解 / 苏格拉底式追问）、禁止直接给答案约束、四档讲解深度、可配置教学风格；
6. **数据安全**：全本地推理、多用户数据隔离、自动滚动备份、带事务回滚的还原、强制离线锁；
7. **硬件自适应**：根据内存与显存推荐三档模型套装，低配自动降级并如实提示。

### 3.3 技术选型

| 选型 | 理由 | 放弃的方案 |
|---|---|---|
| PyQt6 原生控件 + 手写样式表 | 离线、启动快、内存可控、可精确控制外观 | 全站式 Web 界面（体积与内存开销大、启动慢） |
| SQLite（WAL + 外键 + 版本化迁移） | 单机零部署、事务安全、备份即拷贝文件 | 服务型数据库（学生环境难以部署） |
| ChromaDB + 本地嵌入模型 | 向量检索完全本地化 | 云端向量化（隐私、费用、断网不可用） |
| Ollama 统一推理后端 | 部署简单、量化后 CPU 可跑、支持模型常驻 | 自行管理 GGUF（复杂度高）、云端 API（数据外流） |
| 自研 LaTeX 渲染 | 零依赖、可用于任意文本控件、可复制可导出 | 第三方数学渲染库（打包体积大、渲染有延迟） |

## 4 研究方法

1. **需求调研法**：对比学习机、拍照搜题 App、通用 AI 对话、记忆类软件四类产品，梳理出 12 项未被满足的需求（原始调研记录见作品附件）；
2. **文献与资料研究法**：查阅间隔重复（SM-2 算法）、检索增强生成、量化模型推理等相关资料，确定算法与架构路线；
3. **原型迭代开发法**：按"可用闭环 → 补齐能力 → 视觉与体验 → 交付工程"四个阶段迭代，每个阶段以自动化测试作为验收门槛；
4. **实验法**：
   - 实验一：本地模型性能实测（不同任务耗时、模型常驻效果）；
   - 实验二：7B 与 3B 模型在"题目结构化生成"任务上的输出质量对比；
   - 实验三：稳定性与数据安全验证（并发写入、备份还原往返、异常恢复）；
5. **试用与问卷法**（进行中）：邀请同学试用并收集反馈，用于迭代与效果论证。

## 5 研究过程与实验

### 5.1 开发过程（四个阶段）

| 阶段 | 主要内容 | 验收方式 |
|---|---|---|
| 一、可用闭环 | 数据层、模型接入、对话、知识库、错题、闪卡 | 服务层单元测试 |
| 二、补齐能力 | 图像识别、图片增强、练习、组卷、计划、统计、备份 | 端到端流程测试 |
| 三、体验与视觉 | 双主题设计令牌、公式混排、面板渲染回归 | 离屏渲染全部面板走查 |
| 四、交付工程 | 打包、自检、安装包、降级策略、端到端脚本 | 打包产物自检 + 真实安装包验证 |

### 5.2 关键问题攻关（真实研究记录）

**(1) 公式渲染在交付产物中完全失效。**
现象：开发环境公式显示正常，安装后的程序里公式全部退化为源码。
定位：打包配置把数学渲染库（matplotlib）列入了排除列表以控制体积，而渲染管线依赖它。
解决：放弃图片渲染方案，自行实现 LaTeX → HTML 转换器（独立公式用两行表格实现真正的分子/分母上下结构，运算符跨行；行内公式用线性写法）。失败时降级为显示源码，保证不空白、不崩溃、不破坏整段文本。
验证：打包自检探针检查渲染器在打包环境中可用；针对错误公式、含中文的伪公式（如"这件 $5 元"）分别编写了容错测试。

**(2) 导出的 PDF 体积异常。**
现象：一份四道题的练习卷导出 18.68 MB。
定位：将 PDF 逐对象拆解，发现一个 17.47 MB 的流——整个中文字体文件被完整嵌入。
解决：保存前对嵌入字体做子集化，只保留页面实际使用的字形。
结果：18.68 MB → 52 KB（缩小约 360 倍），页面显示与可复制文本完全一致。

**(3) 知识库"相关度"显示为负数。**
现象：检索结果界面显示"相关度：-317.517"。
定位：向量库使用平方欧氏距离，而嵌入向量不是单位向量，距离可达数百；程序按"相似度 = 1 − 距离"计算，导致唯一命中的片段被标记为最不相关。
解决：取回候选向量计算真实余弦相似度（无法取回时退化为单调压缩映射），并限制在 0～1。
结果：同一份讲义的相关度显示为 0.612，符合直觉。

**(4) "硬件推荐 7B 套装"实际运行的是 3B 模型。**
现象：启动引导显示推荐 7B 套装，但实际加载的是 3B 文本模型。
定位：模型名匹配只比较冒号前的系列名，而 3B 与 7B 同属一个系列，代码取"列表中第一个匹配项"，恰好命中了靠前的 3B。
解决：同时匹配系列名与参数量标签，并处理不同写法的别名；同规格缺失时按系列降级。
结果与影响：修复后正确加载 7B；对照实验显示 3B 在数学结构任务上会出现事实性错误（例如把开口向下的二次函数问成"求最小值"），7B 则正确（详见 5.4 实验二）。

**(5) 弹窗关闭后进程静默退出。**
现象：打开文档阅读弹窗后立即关闭，程序直接消失，无异常栈、无日志。
定位：后台渲染回调以匿名函数形式连接到工作线程，控件销毁时不会自动断开；控件已释放而结果到达时回调抛异常，在该框架下未捕获的槽异常会直接终止进程。
解决：对异步回调整体兜底，控件已销毁时安静丢弃结果；同类问题还发现并修复了淡入动画特效的释放时机错误（会导致内存访问越界）。

**(6) 安装包在非系统盘安装失败（真实用户反馈）。**
现象：安装到 `D:\APP\PLOS AI` 时报 "Setup was unable to create the directory ... Error 5: 拒绝访问"。
定位：安装程序默认按"当前用户"权限运行（不请求管理员权限），而目标目录及其上级目录（`D:\APP`）的权限不允许该用户写入，因此创建目录被系统拒绝。
解决：①允许在安装向导中改选"为所有用户安装"（按需请求管理员权限）；②安装向导在"选择目标位置"页先做一次真实写入测试，不可写时当场给出原因与三种处理办法，不再走到一半报错；③给安装产物授予用户可修改权限；④程序侧增加兜底——若安装目录不可写，运行时自动把数据目录改到用户的本地应用数据目录，避免"装上了却打不开"。
验证：重新编译安装包后做静默安装实测（退出码 0、程序文件完整、快捷方式创建正常），并用权限限制模拟不可写目录，确认程序自检仍全部通过且数据按要求落到了备选目录。

### 5.3 实验一：本地模型性能实测

测试环境：普通家用电脑，CPU 推理（无 GPU 加速），7B 文本 + 7B 视觉量化模型。

| 任务 | 实测耗时 |
|---|---|
| 图片增强（去笔迹 + 背景净化 + 对比度 + 锐化） | 0.1～0.2 秒 |
| 单张题目识别（含首次加载视觉模型） | 20～24 秒 |
| 批量识别 + 自动切题 | 9～15 秒 |
| 讲义解析切片并向量化入库 | 约 2.5 秒 |
| 知识库语义检索 | 0.1 秒 |
| 结合知识库的问答 | 7～14 秒 |
| 流式对话首字延迟 | 约 0.5 秒 |
| AI 组卷（4 道题） | 6～21 秒 |
| 练习卷导出（Word / PDF） | 0.9 秒（73 KB / 52 KB） |
| 闪卡复习、学习统计、备份与还原 | 毫秒级 |

分析：模型保持常驻（30 分钟）可显著降低重复调用延迟；纯 CPU 推理下视觉识别是主要瓶颈，而检索、渲染、统计等非模型环节均已进入毫秒级。

### 5.4 实验二：7B 与 3B 模型的输出质量对比

设计：对同一知识点，用相同提示词让两档模型生成一道练习题并判断答案合理性。

| 模型 | 生成结果 | 判断 |
|---|---|---|
| 3B（量化） | "已知二次函数 y = −2x² + 8x − 6 的**最小值**为多少？" | **错误**：二次项系数为负，抛物线开口向下，只存在最大值 |
| 7B（量化） | "已知二次函数 y = −2x² + 4x + 1，求该函数的**最大值**。" | 正确 |

结论：在教育结构化任务中，7B 相对 3B 有质的差别。这一结果为"硬件自适应模型套装"设计提供了直接依据——在算力允许时应优先使用 7B，低配环境需明确提示能力边界，而不是假装功能等同。

### 5.5 实验三：稳定性与数据安全验证

- **多用户数据隔离**：新建第二用户后，看不到第一用户的错题、闪卡与文档；
- **备份还原往返一致性**：导出完整备份（含附件）后还原，错题数量与内容一致，还原过程带失败回滚；
- **并发写入**：多线程并发写入场景下数据不丢失（数据库连接加锁 + 事务上下文）；
- **日志与崩溃捕获**：全流程运行日志无 ERROR / Traceback，异常被全局捕获器记录；
- **打包产物验证**：在打包后的程序中实际执行导入链检查、插件资源检查、Word/PDF 生成、图像增强、公式渲染五项自检。

## 6 结果与分析

### 6.1 系统完成度

- 24 个面板模块（19 项主功能），41 个业务服务模块，30 张数据表，5 个版本化迁移；
- 14 个内置插件 + 4 个商店插件，验证插件机制可在不改动主程序的情况下扩展功能；
- 交付产物：PyInstaller 目录模式程序 + 安装包（405 MB）。

### 6.2 功能闭环验证

以"一个学生一天"为主线编写端到端脚本，把数据目录指向空白沙箱（等价于全新安装）连续执行 41 项检查并全部通过，覆盖：建档、讲义导入、语义检索、知识库问答、流式对话、拍照识题、批量识别切题、错题入库与自动打标、掌握度与薄弱点、导出练习卷、AI 组卷、错题转闪卡与复习、自适应出题判分、学习计划生成与错题驱动调优、术语提取、学习统计、备份与还原、多用户隔离、演示数据加载、12 个面板在浅色/深色下的渲染。

### 6.3 工程质量数据

- 自动化测试 304 项全部通过（含公式渲染、图像增强算法、试卷导出、备份还原、多用户隔离、界面渲染等）；
- 端到端检查 41 项全部通过（真实调用本地模型）；
- 打包自检：插件 14 个内置 / 4 个商店、试卷导出可用、图像增强可用、公式渲染可用。

### 6.4 离线可用性

在断开网络连接的状态下，对话、识别、出题、复习、导出、备份等全部功能正常；系统中唯一需要网络的路径为可选的模型下载与教材导入，并可由"强制纯离线锁"整体关闭。代码层不含任何遥测或后台上传逻辑。

### 6.5 分析：小模型能力的补偿设计

本地小模型在通用问答上不如云端大模型，但在受限教学场景中可以通过三项设计补偿：

1. **结构化工作流**：把"自由问答"转化为"固定格式的结构化任务"（题目切分、知识点打标、难度评分），输出可校验；
2. **提示词约束**：明确字段范围与语言要求（例如强制中文知识点），显著降低无效输出；
3. **程序化校验与降级**：解析失败时回退到安全实现（如公式降级为源码、模型不可用时保留本地功能），避免"一处失败导致整体不可用"。

## 7 创新点

### 7.1 错题驱动的学习闭环编排

大多数工具把错题当成"存档"，本项目把错题当成"驱动信号"：新增错题会向当前活跃学习计划自动插入针对性复习任务，掌握度变化会触发任务优先级重排，每一次调整都留下可查询的调优记录。设计难点在于错题服务与计划服务之间是双向依赖，本研究采用"服务装配完成后回挂"的方式解除循环依赖。

### 7.2 零依赖的 LaTeX 公式混排渲染引擎

在不引入任何第三方数学排版库、不使用浏览器内核的前提下，实现了全应用公式与正文混排：独立公式用两行表格构造真实的分子/分母上下结构，运算符跨行；每个公式附带可解析的锚点，从而支持悬停提示与一键复制 LaTeX 源码；解析失败降级为显示源码。渲染贯通到表格单元格、列表项与文档导出（Word 原生公式、PDF 上下结构绘制）。该设计使安装包不再依赖上百 MB 的科学计算库。

### 7.3 不依赖模型的图片增强预处理

在识别前用纯 CPU 图像处理提升识别质量，包含去手写笔迹、背景净化、对比度增强、锐化、倾斜校正与四点透视裁切。其中"区分手写笔迹与印刷内容"是关键难点：采用颜色与饱和度判别 + 矩形框豁免 + 线条抖动分析，避免误删印刷表格线与文字笔画；并且做到"只勾选去笔迹时不改变整图色调"，保证处理结果可预期。

### 7.4 带教学法约束的对话编排

把教学法做成可切换的编排参数而非固定提示词：教学模式（讲解式 / 苏格拉底式追问）、禁止直接给答案的强约束、四档讲解深度、可配置教学风格（鼓励/严格、深浅、举例方式）。四者自由组合后统一注入消息拼装流程，使"AI 不给答案而是引导思考"成为系统行为而非模型自觉。

### 7.5 以架构保证数据主权

不以"承诺不联网"来宣称隐私，而是让离线成为结构属性：三类模型全部本地推理；提供强制离线锁关闭所有在线入口；多用户数据在表级隔离；备份与还原带事务回滚保护；全局崩溃捕获保证异常不静默丢数据。

### 7.6 硬件自适应的模型套装与降级策略

依据内存/显存推荐三档模型套装，并按机器上真实存在的模型名解析（同时匹配系列名与参数量，处理别名差异）。低配环境自动关闭视觉识别与图表组件并如实提示降级，避免"功能存在但不可用"的误导。

### 7.7 把"可交付"作为功能设计

自建三层验证体系：304 项自动化测试、41 项真实模型端到端检查、打包后自检探针（在打包环境中真实执行导入链、插件、导出、增强、公式渲染）。每一次修复都补充回归用例并记录成因，使系统具备持续可维护性。

## 8 研究结论

1. 在普通家用电脑上部署本地大模型并支撑完整的学习闭环在技术上可行，"离线 + 免费 + 数据不出本机"不是性能上的牺牲项，而是可以通过工程取舍同时实现的目标；
2. 本地小模型的能力边界可以通过"结构化工作流 + 提示词约束 + 程序化校验与降级"的组合设计在教育场景中被有效补偿，但在数学推理等强逻辑任务上仍与更大参数模型存在质的差距，因此硬件自适应的模型选择是必要的；
3. 把错题作为驱动信号、让学习计划随学习状态动态调整，是提升学习工具实用性的关键设计，且实现上需要解决服务间的循环依赖；
4. 桌面端 AI 应用的交付质量取决于工程体系（自动化测试、打包自检、降级策略），而非单一功能是否实现；本研究中四个"测试全绿却真实存在"的缺陷（字体未子集化导致 PDF 体积异常、相关度为负、模型选型失效、离线模板任务重复）都是在模拟真实使用的端到端测试中被发现的。

## 9 不足与展望

**不足：**

1. 本地小模型在复杂数学推理上的准确性仍有限，需要更谨慎的质量提示与结果核对；
2. 视觉识别对内存要求较高（视觉模型最小约 3 GB），低配设备需关闭该功能；
3. 知识图谱目前基于共现统计，尚未实现真正的知识结构推理；
4. 缺少跨设备同步能力，多用户仅限同一台电脑；
5. 主观题批改的采分点抽取稳定性不足，只能作为参考。

**展望：**

1. 由错题相似度驱动的"同类题推荐与自动变式"，把重做变成做等价题；
2. 让计划调整完全可解释（每条调整可展开查看原因）；
3. 视觉模型按需加载与及时释放，降低低配设备的内存压力；
4. 引入关键词与语义混合检索，缓解"问法与讲义用词不一致"的检索失败；
5. 跨平台适配（至少在 macOS 上验证）。
